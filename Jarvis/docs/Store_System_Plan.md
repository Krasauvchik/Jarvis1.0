# План системы для магазина: учёт, аналитика, авто-заказ, облако

## Цели

- **Учёт** — корректный учёт товаров, остатков, приходов/расходов.
- **Мониторинг продаж** — кассовые чеки, отчёты по выручке, по сменам.
- **Авто-заказ** — автоматическое формирование заказа поставщику при достижении порогов остатков.
- **Аналитика** — отчёты, тренды, маржинальность, ABC/XYZ при необходимости.
- **Облако** — всё на вашем сервере: данные, бэкапы, доступ с нескольких точек.

---

## 1. Общая архитектура

```
┌─────────────────────────────────────────────────────────────────┐
│                        ВАШ СЕРВЕР (VPS/облако)                   │
├─────────────────────────────────────────────────────────────────┤
│  Backend API (REST/WebSocket)  │  База данных  │  Файлы/бэкапы   │
│  - Аутентификация             │  PostgreSQL   │  - экспорты     │
│  - Товары, остатки, продажи   │  или MySQL    │  - чеки, фото   │
│  - Заказы поставщикам         │               │                 │
│  - Аналитика, отчёты          │               │                 │
└─────────────────────────────────────────────────────────────────┘
         │                    │                    │
         ▼                    ▼                    ▼
   ┌──────────┐        ┌──────────┐        ┌──────────┐
   │ Касса/   │        │ Планшет/ │        │ Админка  │
   │ терминал │        │ склад    │        │ (браузер)│
   └──────────┘        └──────────┘        └──────────┘
```

- **Сервер**: ваш VPS (например, Timeweb, Selectel, AWS, или свой железный сервер).
- **Backend**: один API для кассы, склада и веб-админки.
- **БД**: одна база — один источник правды по товарам, продажам и заказам.

---

## 2. Что поднять на сервере

| Компонент        | Назначение |
|------------------|------------|
| **API (бэкенд)** | Логика: товары, продажи, заказы, пользователи, отчёты. Язык: Python (FastAPI) или Node.js — как вам удобнее. |
| **База данных**  | PostgreSQL (предпочтительно) или MySQL. Хранение товаров, остатков, чеков, заказов, настроек авто-заказа. |
| **Очереди (опц.)** | Redis + Celery (Python) или Bull (Node) — для фоновых задач: пересчёт остатков, отправка заказов, выгрузки. |
| **Хранилище**    | Директория или S3-совместимое хранилище для экспортов, бэкапов, приложений к чекам. |
| **Reverse proxy**| Nginx — раздача API, SSL (Let's Encrypt), при желании — статика админки. |
| **Резервное копирование** | Скрипты бэкапа БД и файлов (cron), хранение на том же сервере или в облаке. |

Минимальный старт: **API + PostgreSQL + Nginx**. Очереди и S3 можно добавить на втором этапе.

## 3. Учёт и мониторинг продаж

### 3.1 Модель данных (упрощённо)

- **Товары**: id, название, артикул, штрихкод, единица (шт/кг/л), закупочная цена, цена продажи, категория, мин. остаток для авто-заказа.
- **Остатки**: товар, склад/точка, количество, последнее изменение.
- **Продажи**: чек = заголовок (дата, касса, смена, сумма) + строки (товар, кол-во, цена, сумма).
- **Приходы/расходы**: документы прихода от поставщика, списания, перемещения — для учёта и пересчёта остатков.

### 3.2 Мониторинг продаж

- **Смены**: открытие/закрытие смены, итог по смене (сумма продаж, количество чеков).
- **Отчёты**: выручка по дням/неделям/месяцам, топ товаров, средний чек.
- **Оповещения** (опционально): уведомления в Telegram/email при закрытии смены или при падении выручки ниже порога.

Реализация: эндпоинты API (например, `GET /reports/sales?from=&to=`) и экраны в админке/кассе с графиками и таблицами.

## 4. Авто-заказ

- **Правила**: по каждому товару (или группе) — минимальный остаток и «шаг заказа» (кратное количество).
- **Триггер**: при продаже (или при проведении прихода/списания) пересчитывается остаток; если остаток &lt; минимума — создаётся позиция в «заказе поставщику».
- **Черновик заказа**: накопление позиций за период (день/неделя), затем ответственный просматривает, правит и отправляет поставщику (вручную по email/мессенджеру или через интеграцию, если позже появится).
- **Учёт заказов**: статусы «черновик», «отправлен», «частично получен», «получен» — чтобы не терять историю и не дублировать заказы.

Сервер хранит правила и историю заказов; пересчёт остатков можно делать в API при каждой продаже или фоновой задачей (очередь).

---

## 5. Аналитика

- **Отчёты**: продажи по периодам, по товарам, по категориям, по кассам.
- **Остатки и оборачиваемость**: текущие остатки, сколько дней хватит при текущих продажах (опционально).
- **Маржинальность**: (выручка − закупка) по товарам/категориям, если ведёте закупочные цены.
- **Экспорт**: Excel/CSV для бухгалтерии или отчётности.

Всё это — запросы к БД и эндпоинты API; визуализация — в веб-админке или в отдельном дашборде.

---

## 6. Облачное хранение и безопасность

- **Все данные на вашем сервере**: БД и файлы на VPS/облаке, к которым есть только у вас (и у приложений по ключам/логинам).
- **Доступ**: только по HTTPS; API с токенами (JWT) или сессиями; разделение ролей (кассир, кладовщик, админ).
- **Бэкапы**: ежедневный дамп БД + копирование файлов; хранение 7–30 дней, при возможности — вынос копий на другой сервер/облако.

## 7. Поэтапный план внедрения

### Этап 1: Фундамент (1–2 недели)

1. Арендовать VPS, настроить ОС, Nginx, SSL.
2. Развернуть PostgreSQL, создать схему: товары, остатки, пользователи.
3. Реализовать простой API: CRUD товаров, обновление остатков, аутентификация.
4. Базовая веб-страница (админка): список товаров, остатки, добавление/редактирование.

### Этап 2: Продажи и учёт (1–2 недели)

1. Таблицы: чеки, строки чеков, смены.
2. API: регистрация продажи (создание чека и списание остатков), открытие/закрытие смены.
3. Касса: простое приложение (веб или десктоп) — выбор товара/штрихкод, количество, печать чека (по возможности).
4. Отчёт по продажам за день/период в админке.

### Этап 3: Авто-заказ (около недели)

1. В товарах — поля «мин. остаток», «шаг заказа», привязка к поставщику (справочник).
2. При проведении продажи (или раз в N минут фоновой задачей) — проверка остатков и формирование позиций заказа.
3. Экран «Заказы поставщикам»: черновик, правка, отметка «отправлен»/«получен».

### Этап 4: Аналитика и экспорт (около недели)

1. Отчёты: выручка по дням, топ товаров, маржа (если есть закупка).
2. Экспорт в Excel/CSV.
3. Дашборд с основными цифрами (опционально).

### Этап 5: Укрепление и масштаб

1. Регулярные бэкапы, мониторинг сервера.
2. Интеграция с фискальными данными (54-ФЗ и т.п.) — по требованию.
3. Мобильное приложение для склада/приёмки или доработка веб-интерфейса.

- [ ] Спроектировать схему БД (товары, остатки, чеки, заказы, пользователи).
- [ ] Реализовать API (учёт, продажи, смены).
- [ ] Сделать веб-админку (товары, остатки, отчёты по продажам).
- [ ] Подключить кассу/терминал к API (продажи, печать чека при возможности).
- [ ] Добавить правила авто-заказа и экран заказов поставщикам.
- [ ] Ввести аналитику и экспорт.
- [ ] Настроить бэкапы и доступ только по HTTPS.

Если опишете текущий процесс (как сейчас считаете товар, кто формирует заказы, есть ли касса), можно сузить план под ваш кейс и выбрать первый минимальный набор функций для запуска за 2–3 недели.
